# 특수능력 모듈 라이브러리

증강 콘텐츠를 채우지 않고 재사용할 규칙 부품을 준비한 단계입니다. Unity 없이 실행되는 순수 C#이며 기존 경기, 저장, Steam 프로토콜에는 연결하지 않았습니다. 따라서 현재 플레이에 능력이 새로 발동하지 않습니다.

## 구현 범위

`Assets/Marble/Core/AbilityModules.cs`에 32개 불변 정의와 공통 처리기가 있습니다.

- 발동 조건: 통행료 지불/수입, 건설 견적, 구매 견적, 월급, 세금, 주사위, 이동 거리, 착지, 턴 시작/종료, 공격.
- 대상: 소유자, 지정 상대, 지정 타일. 대상이 없으면 발동/소모하지 않습니다.
- 옵션: 확률, 소유자 턴 기준 쿨타임, 최대 사용 횟수(0=무제한), 상태 지속시간 메타데이터.
- 처리 순서: 모듈 ID의 ordinal 순서. 등록 순서에 의존하지 않습니다. 같은 ID는 한 로드아웃에 하나만 등록합니다.
- 난수: seed/소유자/모듈 ID/이벤트 sequence에서 결정. 게임 본체의 난수 상태를 소비하지 않습니다.
- 이벤트 sequence는 로드아웃 전체에서 단조 증가해야 하며 중복/역행을 거절합니다. 소유자 턴도 역행할 수 없습니다.
- 수치 결과는 0~1조로 제한하며 정수 나눗셈으로 버림합니다. 주사위의 실제 합 상한 등 도메인별 제한은 경기 어댑터가 적용해야 합니다.

## 준비된 32종

| 분류 | 모듈 |
|---|---|
| 통행료 5 | 지불 25% 할인, 일회 면제, 100 정액 경감, 수입 30% 증가, 수입 50 추가 |
| 건설/구매 4 | 건설비 20% 할인, 일회 무료 건설, 땅값 15% 할인, 일회 구매 100 할인 |
| 월급/세금 4 | 월급 25% 증가, 월급 100 추가, 세금 50% 감면, 일회 세금 면제 |
| 거리 수치 4 | 주사위 합 +1, 주사위 합 -1, 이동 거리 +2, 이동 거리 반감 |
| 이동 명령 3 | 착지 후 +2칸, 착지 후 -1칸, 일회 출발지 귀환 |
| 상태 명령 12 | 물방울 가두기, 이동 봉쇄, 역방향, 통행료 방어막, 공격 방어막, 반사, 끌어당기기 표식, 밀어내기 표식, 인수 방어, 건설 봉쇄, 땅 통행료 강화/억제 표식 |

값은 기능 검증용 초기값입니다. 등급/증강 이름/아이콘/실제 제공 목록은 비워둡니다.

## 사용 예

```csharp
var loadout = new AbilityLoadout(owner: 0, seed: 123);
loadout.Add(AbilityModules.Get("toll.discount"));
var result = loadout.Resolve(new AbilityEvent(
    sequence: 0, trigger: AbilityTrigger.TollPaid,
    owner: 0, other: 1, tile: 5, ownerTurn: 0, value: 400));
// result.Value == 300
```

원하는 옵션은 `AbilityModule` 생성자로 새로운 고유 ID를 주어 만듭니다. 같은 기능을 사용하는 증강과 황금열쇠가 별도 사용 횟수를 가져야 한다면 ID도 분리해야 합니다. 기본 모듈 최대 64개이며 증강 보유 최대 8개 제한과는 별개입니다. 한 증강이 여러 부품을 가질 수 있습니다.

## 실제 경기 연결 시 필요한 작업

수치 모듈 17종은 결과값 계산까지 구현했습니다. 이동 3종과 상태 12종은 typed intent 생성까지 구현했습니다. 상태 이름만으로 현재 경기의 말을 가두거나 이동시키지는 않습니다.

추후 경기 어댑터에서 호스트 권한, 공격 대상의 생존 여부, 방어/반사 우선순위, 상태 중첩/해제/만료, 이동 중 출발지 월급과 재착지 처리, 효과 연쇄 상한을 정하고 실행해야 합니다. 끌기/밀기 거리와 타일 강화 배율도 그때 정의해야 합니다. 타일 대상 intent의 지속시간은 모듈 소유자의 턴 단위로 해석하도록 메타데이터만 제공합니다.

로드아웃은 현재 메모리에만 있으며 사용 횟수/쿨타임 복원, 경기 replay/hash/네트워크 검증은 아직 연결하지 않았습니다. 단순 견적 조회에 Resolve를 호출하면 소모되므로, 실제 연결 시 조회와 확정 이벤트를 분리해야 합니다.

## 검증

`Validation/VerifySource.ps1` 통과: 기존 141개 + 신규 16개 = 157개. 전체 Unity 런타임/에디터 C# 컴파일 통과. 신규 검사는 할인 계산, 일회 소모, 등록 순서 독립성, 대상 누락, 확률 재현, 쿨타임, 중복 이벤트 거절, 수치 범위, 이동/상태 명령을 다룹니다. Unity 실행/실제 경기 동작/새 실행 파일 빌드는 수행하지 않았습니다.
