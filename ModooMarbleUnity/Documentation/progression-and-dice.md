# 도전과제·외형 해금·카드별 리롤·주사위 컨트롤

0.10.0 소스 구현. 배포 폴더의 실행 파일은 이전 0.8.0이다.

## 도전과제와 보상

| Steam API 이름 | 조건 | 해금 보상 |
|---|---|---|
| WC_FIRST_MATCH | 첫 경기 결과 도달 | 구릿빛 주사위 |
| WC_FIRST_BUILD | 자신의 첫 건물 건설 | 바다 주사위 |
| WC_FIRST_WIN | 첫 경기 1위 | 왕관 탐험가 |
| WC_THREE_LAPS | 한 경기에서 출발지 세 번 통과 | 황금 주사위 |
| WC_GOLDEN_REROLL | 황금 리롤 사용 | 프리즘 탐험가 |
| WC_DICE_TARGET | 주사위 컨트롤 목표 합계 적중 | 프리즘 주사위 |

기본 로봇 4종과 기본 주사위는 처음부터 선택 가능하다. 추가 로봇 2종과 주사위 4종은 해당 도전과제로 해금한다. 메인 메뉴 → 캐릭터 커스터마이징에서 해금된 외형을 장착하고 미리 볼 수 있다. **도전과제 · 해금 조건** 버튼에서 조건·보상·달성 상태를 확인한다. 왕관과 프리즘 날개는 직접 생성한 도형이며 주사위는 표면과 눈의 색상을 구분한다. 외형은 게임 능력치를 바꾸지 않는다.

외형·주사위 스킨은 로비, 다른 참가자의 화면, 재동기화, 로컬 저장 v4에 포함된다. 원격 클라이언트의 외형 ID는 범위를 검사하지만 상대의 Steam 업적 보유를 서버에서 검증하는 별도 소유권 서비스는 아직 없다.

## Steam 연결 범위

일반 게임 실행 시 Steam 연결을 시도하고, 실패하면 로컬 기능을 사용한다. 실제 Steam에 연결된 경우 계정 ID별로 진행·장착 외형을 저장한다. Steam 미연결 상태는 독립 로컬 프로필이다. 다른 계정에 로컬 달성을 자동 복사하지 않는다.

전용 App ID에서는 GetAchievement로 기존 달성을 읽어 외형을 복원하고, 게임 중 달성은 SetAchievement → StoreStats로 전달한다. UserStatsStored 성공 콜백을 받아야 동기화 완료로 간주한다. 오프라인·요청 실패·실패 콜백·응답 시간 초과는 미확인 상태를 유지하고 재시도한다. 새 SDK에서는 Steam 클라이언트가 실행 전 업적을 동기화하며 사용 중인 Steamworks.NET에는 RequestCurrentStats 함수가 없다.

현재 App ID 480은 이 프로젝트 전용 업적 스키마를 관리할 수 없는 개발 설정이므로 Steam 업적 쓰기는 비활성화하고 게임 내 해금만 저장한다. **전용 App ID 발급·업적 등록·게시·실계정 검증은 미완료다.** 이 작업에서는 외부 설정을 변경하지 않았다.

나중에 연결을 활성화할 때:

1. 전용 Steam 앱의 Stats & Achievements에 위 6개 API 이름을 동일하게 등록하고 표시 이름·설명·잠금/해금 아이콘을 설정·게시한다. `steam-achievements.json`은 등록 참고 목록이며 Steam의 공식 가져오기 파일은 아니다.
2. Assets/StreamingAssets/steam-config.json의 appId를 그 전용 ID로 변경한다. 출시 설정에서는 developmentAppId를 false로 둔다.
3. 새 Windows 빌드에서 실제 계정으로 달성·서버 저장·다시 실행 후 읽기·외형 복원을 검증한다.

Steam 업적 API 기준: [Valve ISteamUserStats](https://partner.steamgames.com/doc/api/ISteamUserStats). 실제 함수 제공 여부는 프로젝트에 포함된 Steamworks.NET 2025.164.1 소스도 확인했다.

## 카드별 리롤과 황금 리롤

- 매 증강 선택 페이즈에서 **카드 3장 각각 1회** 리롤할 수 있다. 한 장을 리롤해도 다른 두 장은 유지된다.
- 각 카드 아래의 리롤 버튼을 누르거나 1/2/3으로 선택 후 R을 누른다. 선택 후보가 없으면 R은 사용 가능한 첫 카드에 적용한다.
- 일반 리롤은 해당 카드 등급을 유지한다. 현재 증강 내용은 요청대로 계속 비어 있으며 카드의 리롤 상태·등급·선택만 처리한다.
- 기본 황금 등장 확률은 **플레이어별·페이즈별 10%**다. Game.GoldenRerollChancePercent에서 조정 가능하다.
- 황금이 등장한 경우 그 페이즈에서 **처음 리롤한 카드 한 장**에 자동 적용해 결과를 브론즈→실버→골드→프리즘으로 한 등급 올린다. 프리즘에서는 최고 등급을 유지하면서 황금 사용권을 소모한다.
- 어느 카드를 리롤하든 황금 사용권은 한 번 소모된다. 남아 있는 카드 리롤은 모두 일반 리롤이다. 황금 적용을 받지 않은 카드의 등급은 바뀌지 않는다.
- 다음 페이즈에는 카드별 리롤을 초기화하고 황금 등장 여부를 새로 결정한다. 일반·특수 증강 페이즈에 같은 규칙을 적용한다.
- 황금 등장 여부는 게임 시드·페이즈·좌석으로 결정해 네트워크 도착 순서에 영향을 받지 않고 주사위 난수를 소비하지 않는다. 모든 기록은 저장·리플레이·상태 복구에 포함한다.

## 주사위 컨트롤

짧은 ROLL 게이지는 낮은 합계, 긴 게이지는 높은 합계의 확률을 높인다.

**주사위 버튼 또는 Space를 누르고 있다가 놓으면** 왕복 게이지가 멈추고 굴린다. 자유·홀수·짝수를 먼저 고를 수 있으며 홀·짝은 두 주사위의 합계에 적용한다. 목표 합계와 보드의 예상 칸을 표시하지만 도착을 보장하지 않는다. 홀·짝을 선택하면 표시 목표도 가능한 합계로 보정한다. 더블·연속 더블·무인도 규칙은 기존 엔진을 따른다.

게이지는 0~10단계 입력이며, 목표와 가까운 주사위 조합에 `(13 - |합계 - 목표|)^3` 가중치를 준다. 홀·짝 조건을 만족하지 않는 조합은 제외한다. 허용된 조합은 목표와 달라도 나올 수 있다. 시간·마우스 좌표 대신 최종 게이지 단계와 홀·짝만 호스트에 보내고, 호스트가 결정적 난수로 굴림을 확정한다. AI의 일반 주사위 굴림 경로도 유지한다.

## 검증 상태

Validation/VerifySource.ps1: 규칙 22·건설 11·증강 18·플레이 루프 5·온라인 29·진행/주사위 12 = **97개 통과**. 전체 런타임과 에디터 소스를 Unity 제공 Roslyn 및 Unity 참조 어셈블리로 컴파일했다. 64회 AI 경기와 12회 인메모리 온라인 경기 검사도 포함한다.

카드별 예산, 황금 1회, 프리즘 상한, 다른 카드 선택 시 메타데이터, 네트워크 오류 후 황금 상태 복원, 홀·짝·게이지 확률 방향, 잘못된 입력, 목표 적중 소유자, 외형 잠금, Steam 저장 실패·캐시 읽기·성공 콜백·재시도를 검사했다.

새 실행 파일 빌드·실제 UI 입력과 화면·실제 두 Steam 계정·전용 App ID의 도전과제 저장은 아직 검증하지 않았다. 결과: Validation/progression-source-validation.json.
